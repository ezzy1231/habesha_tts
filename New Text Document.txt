  Part 3: Deploy the Backend to Google Cloud Run

   1. Enable APIs in Google Cloud:
       * Go to the Google Cloud Console (https://console.cloud.google.com/).
       * In the top search bar, find and enable the Cloud Run API and Artifact Registry API.

   2. Configure Docker:
       * Run this command once to allow your local Docker to connect to Google's Artifact Registry:

   1         gcloud auth configure-docker us-central1-docker.pkg.dev
          (You can replace `us-central1` with a region closer to you).

   3. Create an Artifact Registry Repository:
       * This is where your container image will be stored. Choose a name for your repository (e.g., habeshatts-repo).
   1         gcloud artifacts repositories create habeshatts-repo --repository-format=docker --location=us-central1

   4. Build & Push Your Backend Image:
       * This command builds your Dockerfile and pushes the resulting image to the repository you just created.
       * Important: Replace [PROJECT_ID] with your actual Google Cloud Project ID.

   1         gcloud builds submit --tag us-central1-docker.pkg.dev/[PROJECT_ID]/habeshatts-repo/habeshatts-backend:latest .

   5. Deploy to Cloud Run:
       * Now, deploy the image from the registry to a new Cloud Run service.

   1         gcloud run deploy habeshatts-backend \
   2           --image us-central1-docker.pkg.dev/[PROJECT_ID]/habeshatts-repo/habeshatts-backend:latest \
   3           --platform managed \
   4           --region us-central1 \
   5           --allow-unauthenticated
       * When prompted, confirm the service name and region.
       * Cloud Run will give you a URL for your backend service.

   6. Set Environment Variables & Secrets:
       * Go to the Cloud Run section in the Google Cloud Console and find your habeshatts-backend service.
       * Click Edit & Deploy New Revision.
       * Go to the Variables & Secrets tab.
       * Add all the necessary environment variables from your .env.example file (DATABASE_URL, TELEGRAM_BOT_TOKEN, etc.). Use the Render PostgreSQL connection string for DATABASE_URL.
       * For GOOGLE_APPLICATION_CREDENTIALS, it's best to use Secret Manager:
           1. Go to Secret Manager in the Cloud Console and create a new secret.
           2. Name it google-credentials and paste the contents of your .json key file as the value.
           3. Back in Cloud Run, under the Secrets section, click Reference a Secret.
           4. Select the google-credentials secret.
           5. Set the "Reference method" to Exposed as volume.
           6. Set the "Mount path" to /etc/secrets/.
           7. Finally, add an environment variable named GOOGLE_APPLICATION_CREDENTIALS and set its value to /etc/secrets/google-credentials.json (or whatever you named the file).
